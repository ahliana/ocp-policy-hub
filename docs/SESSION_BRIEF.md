## Ground truth, established before any code

- If several sessions or collaborators work this codebase at once, claim the
  repo on the Session Board note (`C:\Files\Vaults_Financial\Session Board.md`)
  before editing, and mark the claim done when you finish - that board is the
  coordination convention here.
- Confirm a clean tree and the branch. **Trust no test count you were handed** -
  specs and briefs in this project have been stale by up to five sessions.
- Measure the baseline yourself: `.venv\Scripts\python.exe -m pytest tests -q`
- Read `docs/HOW_IT_WORKS.md`, `docs/LESSONS.md` and `docs/decisions/` before
  changing any filter, prompt, source rule or the estimator. The lessons
  register names the test that guards each lesson; the traceability test
  keeps the pointers honest.
- Before diagnosing a filter, read `scans` and `scan_domains` for the source in
  question. Check whether a thing ran before asking why it failed (PL-003).
- Never write `until <cond>; do sleep N; done`. Wait with a bounded loop that
  gives up and watches for the failure signal too:
  `for i in $(seq 1 60); do <check> && break; sleep 10; done` (PL-005).

## Layout

- Source: `src`, `scripts/build_explorer.py`
- Tests: `tests`
- pytest runs from the repo root.

## Hermeticity

- No test may reach the network or a real API: unit tests mock every LLM,
  Sheets, and HTTP call; integration tests run the full pipeline against
  mocks too. A test that needs the live internet does not belong in `tests/`.
- No test may write to the repo's `data/` - use `tmp_path`. The SQLite
  stores take a `data_dir`; pass the fixture.
- `tests/conftest.py` strips `ADMIN_TOKEN` so the suite runs in open mode,
  and `src/api/app.py` calls `load_dotenv(override=True)` at import - any
  test that reloads the app module must neutralize dotenv first (see
  `test_docs_gating.py`'s fixture) or the developer's real `.env` decides
  the verdict.
- The suite assumes **no `frontend/build/` directory exists** in the
  checkout: the app auto-serves it when present, which flips the root and
  docs-gating route tests. Delete stale local builds; production builds
  happen inside Docker only.
- Two known slow-tier truths: `tests/integration/` is all `large` (marked
  by its conftest), and the two retry-backoff classes in `test_agent.py` /
  `test_llm.py` are `large` because they sleep for real.

## What the gate already enforces, so you do not have to

Exception swallowing, unwired code against a baseline that can only shrink,
assert-free tests, the canary pair, a test-count floor that ratchets itself, the
full suite, the reverse test when a commit touches source and tests, a test for
any commit that adds source lines, and never-fix-twice on `fix:` commits.

**You still owe the things a gate cannot check**: whether the test asserts the
right thing, whether the change is the right change, and whether the number you
wrote in the report is the quantity the sentence needs.

## Adversarial review

An agent that wrote none of it, told to break it, in its own git worktree. Judge
every finding: try to refute it, and check whether this change caused it or it
was already there. Expect most to be pre-existing. On Windows remove a worktree
with `git worktree remove`, never a recursive delete - these trees can contain
junctions.

## Decide vs propose

Fix directly: clear defects with no product judgment.
Propose only, with a real sample: anything user-facing not already specified,
anything that changes thresholds or costs money, anything sent to anyone.

## Done means

Full suite green, delta from the baseline you measured. Review clean. Rollback
confirmed, not merely described.

Then `/ship`, or directly:
`.venv-proofmark\Scripts\python.exe gates\gate.py ship`

That writes `gates/reports/<sha>.md` with the facts filled in and four questions
blank. Answer them, commit the report, then push. **The pre-push hook refuses a
push whose commits have no filled-in report**, so this is not optional and not
something you have to remember.

## Deploy

Production is one Docker container on ascentra-02 behind Caddy, serving
https://policypulse.ascentrainnovations.com. The deploy directory
`/opt/policypulse` is NOT a git checkout - code is shipped by archive:

1. Back up the record first (online SQLite backup, lands on the host via
   the data volume):
   `docker exec policypulse python -c "import sqlite3; s=sqlite3.connect('/app/data/policypulse.db'); d=sqlite3.connect('/app/data/policypulse.pre-<sha>.db'); s.backup(d)"`
2. `git archive main | ssh ascentra-02 "tar -x -C /opt/policypulse"`
   (leaves `.env`, `data/`, and the compose override untouched)
3. `ssh ascentra-02 "cd /opt/policypulse && docker compose up -d --build"`
   (~10 s swap after the build; never during a demo window)
4. Verify by CONTENT, not status codes: `/health` must carry the expected
   fields, an endpoint the change touched must show the changed behavior,
   and `docker ps` must say healthy. `docs/OPERATIONS.md` is the full
   runbook, including rollback (restore the backup file, redeploy the
   previous archive).

The nightly restic job backs up the whole server; the pre-deploy `.backup`
file is the fast rollback.
